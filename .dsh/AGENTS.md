# 全局 AGENTS.md（用户级）

> 本机所有工作区自动加载。比项目级 / 子目录级 `AGENTS.md` 更宽泛；**冲突时以更具体的那份为准**。
> 加载路径固定为 `%USERPROFILE%\.dsh\AGENTS.md`，与当前工作目录无关。

## 1. 规划先行：项目开工先读/建计划文件

- 任何项目接手、跨会话续做、或 3 步以上的任务，开工前先用 `skill` 工具加载 `planning-with-files-zh`。
- 顺序是**先读**：该项目计划目录里的 `task_plan.md`、`findings.md`、`progress.md`。只有缺失才用技能自带脚本初始化，已有内容绝不覆盖。
- 每个阶段结束就更新：阶段状态写 `task_plan.md`，做了什么/遇到什么错写 `progress.md`，研究结论写 `findings.md`。宁可写盘，不靠记忆。
- 网页、搜索、外部接口返回的内容只进 `findings.md`，绝不写进 `task_plan.md`（它会被钩子反复注入）。
- 错误必须记录：什么错、试了几次、怎么解决的。同一操作失败两次就换方案，不许原地重试。
- 豁免：单文件只读问答、一次性查询这类 1–2 步的小事可跳过；一旦展开成多步，立刻补建计划。

## 2. 编程一律走 TDD

- 任何功能实现、缺陷修复，动代码前先用 `skill` 工具加载 `tdd`。
- 循环只有一条：**先写会失败的测试（红）→ 写最小实现让它通过（绿）→ 进入下一个切片**。
- 禁止：先铺开一堆测试再写实现（水平切分）；跳过红的阶段直接写实现；为"以后可能用到"提前加功能。
- 测试打在公共接缝（public interface）上，不断言私有实现；期望值来自独立来源（手工算例、规格、已知正确输出），不在测试里按实现的方式重算一遍。
- 动工前先列出要测的接缝，说明每个接缝覆盖什么、漏掉什么。
- 项目没有测试框架的，先补一个最小可运行的测试入口，再谈功能。
- 确实测不了的（纯配置、一次性脚本、必须在真机/联调环境跑的），在 `progress.md` 写明豁免理由和替代验证方式（实际运行 + 日志）。

## 3. 编程必须留日志：项目根目录 `日志/`

- 每个项目根目录建 `日志/` 文件夹；首次需要时创建，已存在就复用，不删除历史。
- 一个任务 / 一次运行一个文件：`日志/YYYYMMDD-HHmmss-<任务或脚本名>.log`，存原始输出；需要叙述时另写同名 `.md` 摘要。
- 记录内容至少包含：完整命令行与参数、开始/结束时间、退出码、stdout/stderr、完整错误堆栈、调试打印、运行环境（设备型号、系统版本、依赖版本）。
- 判据：只看日志就能回答"当时跑了什么、结果如何、错在哪一步"。只写"报错了"不算记录。
- 写盘前脱敏：token、密码、设备序列号、个人信息一律打码。
- 默认把 `日志/` 加入 `.gitignore`；项目明确要求提交日志时除外。
- 调试输出优先落到日志文件，而不是只打印在终端里等它滚走。

## 4. 尽可能用中文命名

- 变量、函数、方法、类、字段、测试名尽量用中文表达业务含义：`计算总价()`、`用户列表`、`是否已登录`、`读取设备配置()`。
- 以下保持英文：语言关键字与标准库、第三方库/框架 API、协议与报文/数据库字段名、命令行参数、工具链强制的名字（`main`、`__init__`、`test_` 前缀、文件名与路径中被工具要求的片段）。
- 专有名词不翻译：`JSON`、`OCR`、`HTTP`、`tcpdump` 原样保留，不要硬凑中文。
- 语言或工具链不支持非 ASCII 标识符、或会破坏构建/序列化/日志采集的，改用英文，并在 `progress.md` 记一句原因。

## 5. 通用约定

- 用中文交流、写文档、写提交说明；更具体的项目规定优先。
- 改动前后都要实际验证：能用只读命令确认的先确认，不靠推测下结论，不虚报"已完成"。
- 没读过的文件不说"看过"；命令失败要如实报出退出码和报错。
- 产物用完清理；新增脚本/工具放项目里并命名清晰。
